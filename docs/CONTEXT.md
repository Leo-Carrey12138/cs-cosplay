## 检测方案现状（2026-10-19 实测后更新）
- 当前实现：ML Kit 通用物体检测（内置模型没有 person 类，只有家居/服饰/食物/场所/植物 5 个大类）
  → 根因：它只找"显眼物体"，所以手机/海报/花纹乱出框，真人远了（像素不足）反而漏检
- V3 实机实测（宿舍）：约 2 米才勉强出绿框，效果糟糕
- 方案 B 落地选型：**MediaPipe Pose（BlazePose，33 关键点）**，理由：深蹲计数项目已有完整经验
  - 绿框 = 关键点包络框，从根上过滤杂物
  - 6 人房间用多姿态模式（num_poses）或分区检测
  - 守 33ms/帧实时预算，必要时隔帧检测 + 跟踪
  - 与方案 A 变焦互补：Pose 管中近距（约 2~8 米），变焦管远距离
  - 自训练模型仍留作后续优化选项，不是当前路径
  - 借鉴①：准心 ROI 裁剪——只分析准心附近区域，省算力换分辨率/射程（来源见"参考系统源码笔记"）
  - 借鉴②：开火瞬间重新识别——开火当场跑一帧，不用缓存帧，消灭"准星移动 vs 旧结果"的竞态

## 参考系统源码笔记（2026-10-19，Electron 局域网真人CS，已通读源码）
- 位置：src/renderer/src/vision/（descriptors.ts 特征、engine.ts 画面分析）、src/main/lanServer.ts（裁决）
- 技术栈：Electron + @vladmandic/human（blazeface 检脸 + faceres 特征向量）+ movenet 姿态；房主电脑当权威服务器（局域网）
- 核心设计：赛前建档（正/背面拍照 → 人脸特征 + 衣着 HSV 直方图/3×3 网格/躯干长宽比）→ 战斗中只裁准心区域、每 130~340ms 一帧 → 识别即命中（无弹道模拟）→ 服务器校验链扣 25 血（100 满血 = 4 枪击倒，5 秒复活）
- 身份判定红线：人脸 ≥0.55 或 衣着 ≥0.7，且第一名领先第二名足够 margin，否则"目标未识别"作废这枪；脸 <24px 放弃脸、靠衣着（10 米外主靠衣服）；全程端侧不上传照片
- 值得借鉴（按优先级）：
  1. **准心 ROI 裁剪**：算力只花准心区域 → 同样帧预算换更高分辨率/更远检测距离，直接缓解"2 米才出框"；与方案 A 变焦叠加（变焦放大后 ROI 内像素更多）
  2. **开火瞬间重新识别**：开火当场重新跑一帧识别，不用 100ms 前的缓存结果
  3. **服务器校验链**：比赛状态/存活/开火冷却/队友误伤免疫/复活 2 秒无敌/击杀计分——可抄进 Firebase 规则
  4. **保守识别原则**：阈值 + 第一二名 margin，认不出宁可作废（与开枪方权威兼容，防误伤兜底）
  5. **双特征身份思路（脸+衣着、建档制）**：target_picker 自动化的升级路线，v0.1 保留手动指认；全程端侧，隐私好讲
  6. **分级识别质量档**（分析间隔 130~340ms）：帧预算管理参考
- 不要照抄：桌面 GPU + 局域网架构与我们 Flutter 手机 + Firebase 差异大；"无弹道、识别即命中"的简化思路与我们一致，可放心沿用
