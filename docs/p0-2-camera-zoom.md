# Issue #4：相机变焦验收

## 实现

- 直接使用现有 camera / CameraX，查询最小、最大倍率并调用 setZoomLevel。
- 初始与重开相机为 1.0x；每次 ±0.5x，最后一步截断到设备上限（如 2.3x）。
- 控件置于底部状态面板下方，取景、准星、射击按钮仍各自独立。
- 初始化未完成、阵亡、后台、变焦处理中和能力查询失败时禁用按钮。
- API 失败保留显示倍率并提示；初始化、变焦、释放串行执行，以代际标记拒绝失效结果。
- 不改变 NV21、分辨率、姿态算法与 FrameMapper。CameraX 的原生变焦应同时作用于预览和分析；不能再给检测框乘倍率，否则会二次放大。每次变焦清空旧框、拒绝旧推理结果，并等待一个检测间隔后接收新帧。这不能代替设备上对 CameraX 裁切/稳定时延的检查。

## 最简单的真机验收

让有 Flutter 环境的组员切换 feature/p0-2-camera-zoom，执行 flutter pub get、flutter analyze、flutter test，再用 USB 连接 Android 手机并执行 flutter run（现有依赖要求 Flutter >=3.44.0 / Dart >=3.12.0）。

1. 进入房间和游戏，对准另一位站立的人。初始显示 1.0x，缩小按钮禁用。
2. 点击放大，确认画面实际放大且显示 1.5x、2.0x；连续快速点击直到上限，确认无越界或崩溃，上限禁用放大。缩小回 1.0x。
3. 在 1x、中间倍率和最大倍率下，将人移到准星附近及两侧，检查框贴着人，框外开火脱靶、框内按现有规则命中；变焦切换时旧框消失。
4. 变焦时按 Home/锁屏，再回应用：预览和识别恢复，显示 1.0x；重复快速前后台切换并退出房间，确认不崩溃。
5. 阵亡后控件禁用；新局恢复识别，后台期间重开也遵守阵亡锁定。拒绝相机权限后按重试，确认可恢复。
6. 尽可能另测仅支持 1x 的设备；相机能力/API 报错需要模拟或故障设备验证，不能仅凭正常设备认定通过。
