# Issue #4：相机变焦与小队模式回归验收

## 合并与实现

- 已合入最新 main `68eea05`（PR #12），以其小队业务逻辑为基础解决 `game_screen.dart` 冲突。
- PR #12 其余 18 个文件与 main 逐字节一致：保留选队/容量限制、队友免疫、25 伤害四枪击倒、击杀事务、5 秒自动复活、2 秒保护、房主重开和原有测试。
- 游戏界面保留敌方列表、所有 CombatOutcome 分支、死亡倒计时、复活保护、小队信息及房主重开结果处理。
- 现有 camera / CameraX 原生变焦：默认 1.0x，每次 ±0.5x，最后一步截断到设备上限；底部面板显示倍率，不遮挡取景、准星或开火。
- 初始化、变焦、死亡/复活同步、释放串行执行。未完成初始化的 controller 由初始化任务独占释放；相机/图像流代际检查阻止失效回调。错误或暂停状态下禁用控件，恢复失败提供重试入口。
- 死亡/复活同步任务执行时读取最新会话状态；后台返回重开相机并恢复 1.0x。同一相机会话内自动复活/重开保留已确认的倍率并恢复图像流。
- 变焦时停止旧图像流、清空旧框、拒绝旧推理结果，恢复图像流后等待一个检测间隔再识别。选人弹窗返回时再次检查画面代际，避免变焦/死亡/后台切换前的命中继续确认。
- 保留 NV21、姿态算法和 FrameMapper，不额外乘变焦倍率。原生变焦应同时作用于 CameraX 预览和分析，但设备实际裁切与稳定时延必须真机核对。

## Android 真机步骤（尚未执行）

建议 3 台 Android 手机（2 台同队、1 台敌队），或让组员协助安装同一版本。

1. 两队选队、自动分配，检查每队最多 3 人和队伍状态；房主开始游戏。
2. 初始倍率 1.0x，缩小禁用；按放大到 1.5x、2.0x、设备上限，再缩小回 1.0x。确认画面实际放大、边界禁用、快速连续点不越界、不崩溃。上限不足 1.5x 的设备按实际能力验收。
3. 1x、中间、最大倍率下，人物位于准星中心及两侧；检查框贴着人物，框外脱靶、框内按原规则进入敌人确认。变焦时旧框消失，弹窗期间切后台后返回不能确认旧命中。
4. 对敌人连续命中四次：100→75→50→25→0；第四枪攻击方击杀数 +1，重复攻击已死目标不得重复计分。检查同队不出现在敌方列表；事务层队友免疫由 combat_rules 测试覆盖，必要时用测试客户端发同队请求核对数据库。
5. 阵亡后预览锁定、控件禁用、显示 5 秒倒计时；自动复活后预览/检测恢复，并有 2 秒保护。保护期间被攻击不扣血，结束后可以扣血。
6. 在变焦调用中分别切后台、锁屏、收到致命伤害；等待复活后再回应用。重复快速前后台切换、退出房间：无黑屏、无旧控制器回调、无重复占用。后台返回应显示 1.0x；仅自动复活应保留已有倍率。
7. 阵亡/复活/变焦中由房主重开：保留队伍、全员满血、击杀清零、死亡和保护清空，相机解锁、图像流恢复。重复数次检查旧复活任务不会影响新局。
8. 拒绝相机权限后重试恢复；如有仅支持 1x 的设备，确认双按钮禁用。API 故障与资源占用恢复仍需故障注入/设备验证，正常设备验收不能替代。
